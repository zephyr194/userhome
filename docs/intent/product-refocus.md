# UserHome 产品重定位：以家目录为底座的开发者工具配置台

日期：2026-11-03
状态：意图已由用户确认（2026-11-03）。方向与证据见 [docs/ideas/product-refocus.md](../ideas/product-refocus.md)。确认后写规格，规格确认前不实现。

## 意图

- **Outcome**：UserHome 从“按模块堆起来的一组页面”改为“以 `~` 为底座、带着具体的事打开就能做完的工具配置台”。
  - **打开即开始做事**：第一屏是焦点在输入框的命令面板（入口形态 A，已定），输入一句话、回车直达任务；模块页退为二级。先显示上次的缓存，后台刷新。
  - **家目录透明（第 0 层）**：`~`、`~/.config`、`~/Library/Application Support` 下的条目按工具聚合，分为配置、凭证、缓存、工具链与运行时、应用数据、受管软件、个人文件、未认领。未认领的单独列出；用户可以手动认领，给条目指定归属工具和类别，下次盘点沿用。
  - **工具透明（第 1 层）**：每个开发工具一张卡片，显示安装来源、版本，以及“五个维度”（源 / 镜像、凭证、网络、位置、版本 / 工具链）的有效值、来自哪一层、被谁覆盖。版本与期望不一致时，按安装来源给出对应的升级命令。
  - **AI 工具可视化配置（第 2 层）**：本机安装的 AI 工具（Claude Code、Codex、Gemini CLI、Copilot CLI 起步）提供包含全部配置项的表单，由官方 schema 生成，改完确认生效。
  - **AI 资源可视化（第 3 层）**：Skill 与 MCP 的跨 agent 矩阵，显示在哪些 agent 可用、来自哪里、版本是否一致，勾选即同步到各 agent 的配置格式。
- **User**：本人。开发者，配置工具的方式是“用到才想起来，去查，去配”，不会浏览。以后用得顺手再考虑同事。
- **Why now**：功能一点点加上去，但打开不知道怎么用，功能含糊而视觉反复打磨；第一次只读盘点就发现多个用户不认识的条目，以及“本机没有 rustup、rust 来自 brew”“当前 Node 与项目要求不一致”这类有效值与直觉不符的情况。
- **Success**：
  - 从打开到开始做事不超过 3 秒；第一屏不出现用户没问的计数和状态。
  - 一次盘点后，`~` 下除个人文件外的每个条目都有归属，或被明确标为未认领；手动认领后下次盘点仍保持。
  - 对首批工具，能直接回答“这个目录下用的是哪个 Node / Java / Python / Rust / Go，由谁决定，怎么升级”。
  - 每个功能写清“一句话意图、完成标准、确认方式”，缺一不进规格；首批任务的完成标准见 idea 文档的“首批任务与完成标准”表。
  - 工具知识（配置层、关键项、查看有效值与确认生效的命令、拥有哪些路径）由 agent 起草，用户只核对，不再需要用户逐个工具细化。
- **Constraint**：
  - 沿用现有安全边界：本地、当前用户权限、不请求 root。
  - 未知条目只读名称与元数据（大小、修改时间），不读内容；只读取工具知识里声明过的配置文件。
  - 凭证一律只显示“是否已配置”，不显示值；受管软件只显示，不提供修改或清理入口。
  - 写入沿用已有的差异预览、备份、确认与写后校验；升级命令先采用“生成命令后在终端打开”，由用户在终端确认。
  - 保持紧凑的信息密度；现有的对比度、reduced-motion、键盘可达性不倒退。
- **Out of scope**：团队分发与配置包；“所有工具”一次覆盖；Raycast 扩展（入口 B）；新的主题与视觉规格（冻结到首批任务通过）；变更时间线作为主产品；跨工具配方；Maven 作为主打（只做有效值只读）。

## 用户给出的原话要点

- 核心：“我期望我电脑应用和配置透明化，在这个基础上可以支持本机安装的 AI 工具能够可视化配置，资源（skill/mcp）可视化。”
- `~`：“核心还是 `~` 目录，不能少了这个，用户目录，大量各种配置混杂其中。”
- 分工：“npm 的配置、maven 配置、rust 配置等等。这些我认为你应该知道，而不是等我去细化。”
- 识别：“配置放在哪里没关系，关键是可识别，后续也可以通过手动方式添加。”
- 升级：“这个时候，就需要判断当前使用什么工具安装，然后调用升级命令。”
- 现状：“产品规划糟糕透了，虽然一点点添加了我需要功能，但是实际，打开的体感很差，不知道怎么用。”
- 入口：“那肯定是 A。”

## 待规格阶段决定或交给用户选择

- **首批切片顺序**（建议）：
  1. 打开体验与命令面板骨架（缓存先显示、意图直达）。
  2. 家目录地图：只读盘点、按工具聚合、未认领列表、手动认领。
  3. 工具卡片：先覆盖 Node（nvm）、Java（sdkman、Maven）、Python（pyenv、uv）、Rust（brew）、Go、git，含安装来源与升级命令。
  4. Skill 与 MCP 跨 agent 矩阵。
  5. AI 工具完整配置表单（在现有 AI 配置基础上由 schema 生成）。
- **现有模块的去向**：概览页删除、降级还是改为“最近做过的任务”；文本与二维码工具是否移出主导航；环境变量与服务是独立入口还是作为工具配置的载体；Caddy 作为首批任务保留在哪一层。
- **命令面板形态**：主窗口内的输入框，还是全局快捷键唤起的独立小窗。
- **升级命令的执行方式**：只在终端打开，还是允许应用直接执行（需要单独评估安全边界）。
- **复用**：现有 `export_sanitized_baseline` 的扫描与分类能否作为第 0 层的起点。
- **尚未完成的两项验证**：Caddy 任务的步骤与耗时记录、Skill 与 MCP 的跨 agent 盘点。盘点结果会影响第 4 步的优先级。
