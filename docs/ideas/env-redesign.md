# 环境变量页重设计：系统环境变量 / 目录 dotenv（已确认 2026-10-23）

## Problem Statement
怎样让开发者一眼看出“这个变量最终是什么值、从哪来、被谁覆盖过”，而不是在 zsh、登录会话、dotenv 几个入口里自己对照？

## 用户答复
- 结构：二级 = 系统环境变量 / 目录 dotenv；三级 tabs：系统 = zsh | 登录会话；dotenv = 每个已授权目录一个 tab（末尾“添加目录”）。
- 同名变量：展示读取链——最终值（高亮）+ 过程值（值、来源文件:行号，按读取顺序）。

## Recommended Direction
一行一个变量名，主列最终值与来源文件:行号；点开看读取链。秘密值遮盖，被覆盖的值也不泄露。保留已有“设置变量/修改”入口。

## Key Assumptions
- [ ] 登录会话每个键只有一条，无过程值，只显示最终值。
- [ ] dotenv 跨文件优先级取决于具体工具，不推断；只对同一文件内重复键做“最后一处生效”，跨文件并列显示。
- [ ] zsh 的读取顺序沿用现有数据（含 appliesTo）。

## MVP Scope
做：两部分菜单、各自 tabs、读取链、dotenv 按目录 tab、保留设置变量入口。

## Not Doing
- 当前进程环境 tab — 用户未选。
- dotenv 跨文件优先级推断 — 工具不统一。
- 变量搜索 — 下一版。

## Open Questions
- 已授权目录很多时 tabs 的溢出处理（横向滚动 / 下拉）。

## 实现偏差（2026-10-30，协调者确认）
- 变量区改为左侧变量列表、右侧选中变量的详情，与 services、ai-config 同结构；不再行内展开读取链。最终生效值与读取链都放在详情里。上文“点开看读取链”由此改为“选中后在右侧看读取链”。
- zsh 的引用值（如 `$BASE/bin`）在可由同一读取链中的前序赋值确定时静态展开；无法确定时保留原文并说明原因。不执行命令。dotenv 的值按文件原文显示，不做展开。
