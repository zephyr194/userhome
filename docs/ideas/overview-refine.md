# 概览页重做：本机开发环境一览（已确认 2026-10-22；开发工具链放下一版）

## Problem Statement
怎样让概览在不滚动、不触发慢读取的前提下，让开发者一眼看清“这台 Mac 上的开发环境是什么样”——装了多少工具、有多少环境变量、有多少服务，而不是把侧栏的每个页面再摆一遍卡片？

## 用户答复（2026-10-22）
- 概览是“自己看”的页面，符合 UserHome 主题：安装了多少工具、有多少变量、开发环境什么的。
- 成功标准：不用滚动就看完；不触发慢读取；与导航不重复。
- 现有内容只保留：系统信息摘要。其余（模块卡片墙、覆盖范围面板、读取摘要按钮、最近操作）不保留，列入“不做”。

## Recommended Direction：事实清单，而不是页面入口
把概览从“舱位墙（每页一张卡）”改成一页“本机事实清单”：
1. 顶部一行：系统信息摘要（macOS 版本、主机名、芯片、磁盘余量）——保留的唯一旧内容。
2. 主体 2×N 的“事实格”，每格 = 一个数字 + 一句话 + 数据新鲜度，例如：
   - 服务：1074 项后台任务（运行中 38）——来自应用启动时已经读好的服务快照，不额外读取；
   - AI 工具：已安装 3 / 4（Claude Code 2.x、Codex …）——来自 AI 工具页的缓存，没有缓存时显示“未读取”并给一个“读取”按钮；
   - 环境变量：dotenv N 个文件 / M 个变量、zsh N 个文件、登录会话 K 个变量——有缓存才显示数字；
   - 应用配置：已登记 N 项、其中存在 M 项；
   - 开发工具链（建议 v2）：node / python / go / rust / java 的版本（需新增只读后端命令，每项 <100ms，不走 launchd 发现）。
3. 每个事实格可点击跳到对应页面并定位到那一项；格子里不放按钮条、不放说明段落。
4. 数据新鲜度：每格右下“刚刚 / 3 分钟前 / 未读取”；整页一个“刷新全部”，只重读已读取过的格子。
5. 打开概览永远不自动触发 >1 秒的读取：只用缓存与启动快照；其余格子显示“未读取”。

为什么这样：侧栏已经负责“去哪”，概览负责“现状是什么”。事实清单是信息，不是导航，所以不重复。

## Key Assumptions to Validate
- [ ] 服务快照在应用启动时已经读取并保存在 AppShell（是：`discovery` 状态）——核对“运行中”数量可直接取得。
- [ ] AI 工具缓存（r5-ai 包）完成后，概览可以只读缓存，不触发检测。
- [ ] 环境变量与应用配置能提供“只读、<1 秒”的计数；否则该格显示“未读取”并提供手动读取。
- [ ] 开发工具链检测是否值得做（v2）：用户是否真的想在概览看到 node/python 版本。

## MVP Scope
- 做：系统信息摘要 + 服务 / AI 工具 / 环境变量 / 应用配置 四个事实格 + 新鲜度 + 点击跳转 + 单屏无滚动（≥1100×700 窗口）。
- 不做（v2）：开发工具链版本（新后端命令）、历史趋势、可自定义排序。

## Not Doing (and Why)
- 模块卡片墙 / “读取摘要”按钮条 — 与侧栏重复，且让概览变成操作页。
- 覆盖范围面板（“部分可用”）— 用户只要求保留系统信息；覆盖信息放到设置/诊断。
- 最近操作 — 属于操作记录，已有入口，不放在概览。
- 自动读取 Caddy / 服务发现 — 5–20 秒的慢读取，违背“不触发慢读取”。
- 看板、图表、仪表盘动画 — 用户已移除看板，概览也不需要装饰。

## Open Questions
- 开发工具链（node/python/go/rust/java 版本）要进 v1 还是 v2？这需要一个新的只读后端命令。
- 事实格是否需要“需要留意”的突出（比如有服务异常）？若要，只做一个数字角标，不做列表。
- 概览在窗口较窄（<1100px）时是单列滚动，还是缩小成更少的格子？
