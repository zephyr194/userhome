# 表单控件、单层选中态与对齐间距（ui-forms）

日期：2026-10-22
状态：设计方向，待规格 SPEC-ui-forms.md 固化。依据：2026-10-22 对运行中的开发版应用（`pnpm tauri dev`，用 computer-use 截图）的只读观察，以及用户的四条反馈。

## 观察到的问题（真机截图证据）

| 反馈 | 观察 |
|---|---|
| 高亮是两个框 | 导航项、列表项、标签页选中时同时出现“1px 橙色虚线框”和“四个橙色 L 角”，角标压在虚线上，视觉上是两层框，角标显得多余 |
| 按钮未对齐 | 工具栏里“看板”和“刷新”高度、基线不同（看板更低且两者几乎相贴）；工具集里“格式化”（实心）与“清空”（无边框）视觉高度不一；Caddy 站点里“删除站点”和“启用此站点”开关不在同一基线 |
| 内容没有间距 | 页头标题贴着顶部；说明文字与工具栏、状态条之间没有留白；Caddy 站点用 `fieldset/legend`，“站点 1”标题压在面板上边缘；字段标签与输入框、开关之间没有层级间距 |
| checkbox 异常 | 开关（`SwitchField`）标签在上、开关在下，且关闭状态只有一个白色圆点（轨道与背景同色，看不到）；工具集的“输出格式”仍是 macOS 原生 popup 控件，与其他控件风格不一致 |
| 其他 | 前一个选中的导航项会残留一块带边框的底（疑似悬停或残留状态，由合成点击触发，待真人使用确认，不在本轮改动范围） |

## 设计方向：一个“强调”，其余安静

**唯一的记忆点：四角锁定。** 选中态只用橙色 L 形角标（实线 2px、臂长 6px）加极浅橙底；**去掉虚线框**，也不再用 1px 橙色实线边。角标之间没有连线，所以只有一层视觉，且仍然是“机甲瞄准框”的语言。其余一切安静：灰阶、1px 发丝线、4px 圆角容器、3px 圆角控件。

### 选中态候选
```
A（推荐）仅角标 + 浅橙底        B 左侧色条 + 浅橙底          C 仅 1px 实线边 + 浅橙底
┌ ┐                              ▌ 概览                        ┌──────────┐
  环境变量   （角标不连线）       ▌ 环境变量（选中）             │ 环境变量 │
└ ┘                                                             └──────────┘
```
取舍：A 保住“四角”这一最初的设计诉求，同时消除“两层框”；B 最干净但失去机甲语言，也无法用于看板舱位和标签页；C 太普通。选 A。

### 状态矩阵（所有可选中元素共用 `.bracket`）
| 状态 | 表现 |
|---|---|
| 默认 | 无装饰 |
| 悬停 | 对角两个灰色 L 角（6px，1px）+ 背景轻微变深 |
| 选中 | 四个橙色 L 角（6px，2px）+ 浅橙底；不画虚线框；`aria-selected`/`aria-current` 保持 |
| 键盘焦点 | **没有外框**：背景用悬停色，文字下方不加线；字段类（输入框、下拉、文本域）边框变橙。这是用户 2026-10-22 的决定（去掉所有元素焦点外框）带来的代价 |
| forced-colors | 角标隐藏，选中改用系统色 `Highlight` 的 1px 实线边；焦点使用系统色 |
| reduced-motion | 无过渡 |

不只靠颜色：选中仍有角标形状，导航项另有“当前”可访问性属性。

## 对齐与间距规则

- **操作行（ActionRow）**：同一行里的按钮、开关、下拉统一用 `h-control-md`（28px）或 `h-control-sm`（24px），`items-center`，`gap-8`；幽灵按钮也保留 1px 透明边，保证与有边框按钮同高。工具栏里的 `BoardToggle` 与“刷新”使用同一个按钮外形。
- **页头**：标题与说明上下各 12px 内边距；工具栏动作与标题垂直居中；页头与状态条之间 0 间隙但有发丝分隔线（现状），状态条与内容之间 16px。
- **面板**：内边距 12px，面板内区块间距 12px，面板之间 16px，页面分区之间 24px（沿用 `--app-space-*`）。禁止 `fieldset/legend` 做面板标题，统一用“标题行”（h3 + 右侧操作）。
- **字段**：标签与控件间距 4px；字段与字段间距 8px；一行两个字段用两列网格。
- **开关与复选框**：控件在左、标签在右，同一行垂直居中；说明文字在下一行缩进到标签起点。

## 表单控件外观
- **Checkbox**：16×16，3px 圆角，1px 灰描边，选中填充橙并显示白色对勾；禁用 50% 透明；错误态红描边。
- **Switch**：轨道 32×18，**关闭态也有轨道**（灰底 + 1px 描边），圆点白色带 1px 描边；开启态橙底。
- **Radio**：同 Checkbox 尺寸，全圆，选中为橙色实心点。
- **下拉（自定义 Listbox）**：触发按钮与输入框同高同描边，右侧 chevron 图标；浮层 4px 圆角、1px 发丝线、与触发按钮等宽；选项行高 28px，当前项带对勾，悬停/键盘高亮用悬停色，不加外框。
- **输入框/文本域**：1px 描边；聚焦时边框变橙（唯一的聚焦提示）；必填标记保持；错误在下方一行红字。

## 工具集输入框
- 输入区默认就是“活跃区”：浅底 + 稍深的 1px 描边，聚焦时橙色描边；右上角“在独立框中打开”（展开图标按钮）。
- 独立框：同页模态（沿用现有 `Modal`），大号等宽文本域，底部“完成”（把文本写回）与“取消”；Esc 等同取消；焦点回到触发按钮。文本只在本次页面状态，与现有隐私声明一致。

## 三级导航
- 层级：**系统工具**（组）→ **环境变量 / Caddy / 应用配置 / AI 配置**（工具）→ **具体工具配置**（工具内的分区）。
- 侧栏：组标题 → 工具项；选中工具时在其下方展开缩进的分区项（硬编码）；其余工具保持折叠。分区选中同样用角标语言（尺寸缩小）。
- 页面内：当前分区决定主内容；路由多一个 `section` 参数，不影响现有 `view=board`。

## Caddy 指令表单
- 每个站点的配置改为“指令行”列表：左侧指令下拉（监听主机、监听端口、上游、HTTPS、访问日志……硬编码目录），右侧该指令对应的值控件，行尾删除。
- 值控件由目录决定：主机、端口用带校验的输入；协议用下拉；HTTPS 的证书/私钥用文件选择；访问日志用开关。
- 校验在值控件下方显示，沿用现有后端校验消息；生成的 Caddyfile 对同一输入保持不变。
- 原文 Caddyfile 模式保留为“高级”分区。

## 不做的事
- 不用 clip-path、渐变、发光、大阴影、新字体。
- 不保留“虚线 + 角标”叠加；不引入第二种选中语言。
- 不在本轮增加聚焦提示之外的键盘装饰（用户已决定去掉焦点外框；若真机使用后觉得键盘不可辨，再单独设计）。
- 不做三级导航的配置化（先硬编码）。
- 不新增 Caddy 后端指令（门禁 G-U3）。

## 待人工判断
真机浅/深主题下角标 6px 是否足够醒目；无焦点外框时键盘用户的可辨度；自定义下拉的键盘与屏幕阅读器；独立框的焦点归还。

## 修订（2026-10-22，用户第二轮反馈）：选中效果改为“滑动指示器”；“图表”指应用图标

### 对上一版选中态的评价（真机截图）
- “仅角标 + 浅橙底”落地后，选中项变成“一块橙底、边缘一圈、里面再缩进四个角”：角标在底色里面，等于外框内套四角，用户评价“太丑”。结论：**角标这条路线整体放弃**，不再做“边框 + 四角”的任何组合。
- 悬停的灰色对角角标同样放弃；悬停只用背景轻微变深。
- 观察到的副作用：前一个被选中的导航项偶尔残留一块带边框的底（合成点击后鼠标没离开）。新方案的悬停只改背景色，不画边框，这类残留不再突兀。

### 新方案：滑动指示器（Slide）
**唯一的记忆点是运动**：列表里只有一个选中指示器，选中项变化时它沿列表滑到新位置，像线性执行机构推到某个挡位。指示器本身极简，不再有任何装饰边。

```
竖向列表（导航、服务、AI 工具、环境文件、设置分组、分区项）
┌────────────────────┐
│  环境变量          │
│▌ Caddy            ◄── 指示器：浅橙底 + 左侧 3px 橙色竖条，圆角 3px，沿列表上下滑动
│  应用配置          │
└────────────────────┘
横向标签页（工具集 JSON/XML/编解码/二维码）
  JSON   XML   编解码   二维码
  ▔▔▔▔▔                      ◄── 指示器：浅橙底 + 底部 2px 橙色横条，沿标签左右滑动
```
- 形态：浅橙底（`--app-selection`）+ 一条橙色实线竖条（竖向列表）或横条（标签页）；无虚线、无角标、无外边框；圆角 3px。
- 运动：位置与尺寸用 120ms `cubic-bezier(0.2, 0.7, 0.2, 1)`（先快后缓，不过冲）过渡；只在选中变化时动，页面加载不做入场动画；`prefers-reduced-motion` 下直接跳到位置。
- 文字：选中项文字加深为前景色并半粗体；不靠颜色单独表达选中——竖条是形状，且保留 `aria-current`/`aria-selected`。
- 悬停：背景轻微变深，无边框无角标；键盘焦点：同悬停（用户已决定去掉焦点外框）。
- 渐进增强：指示器由列表容器的一个伪元素承担，位置由一个 hook 测量选中项后写入 CSS 变量；服务端渲染或尚未测量时，选中项自己显示同样的浅橙底和竖条（所以没有 JS 也不丢选中状态，测试和首屏都稳定）。
- forced-colors：指示器隐藏，选中项使用 `border-inline-start: 3px solid Highlight`。
- 范围：所有“选中一项”的列表与标签页统一使用；舱位墙卡片等不是“选中”语义的容器不用。

### 为什么不用别的
| 备选 | 否决原因 |
|---|---|
| 实线边框 + 浅橙底 | 太普通；也无法表达“滑动” |
| 只加粗左竖条（无滑动） | 没有运动，等于另一个静态标记，不满足“要在列表中滑动” |
| 弹簧过冲动画 | 机械感弱、像消费级应用；且容易分散注意力 |

## 应用图标（用户所说的“图表”）
- 事实：应用里没有柱状图/折线图；真机与资源核对后，“底色和形状都太丑、和整体不搭配”指的是**应用图标**（深绿渐变底 + 圆润 U 形 + 两个圆形滑块）。侧栏左上角的品牌小方块（浅橙底 + 斜线字形）也与之不统一。
- 新图标（已提交 088c255）：冷钢灰深底（`#1D242D`，1024 画布内 824 方块，macOS 栅格），棱角 U 形（切角而非圆弧，内凹也切角）取自“控制舱”语汇；U 口里两条滑轨，一枚钢灰滑块、一枚信号橙滑块（与界面的钢灰 + 信号橙一致）；U 的两个端面各有一条橙色端标。无渐变、无发光。源文件 `src-tauri/icons/icon-source.svg`，用 `pnpm tauri icon` 重新生成。
- 侧栏品牌块：改用同一图形的内联 SVG（`BrandMark`），颜色取令牌，浅/深主题各一套，不再用浅橙底斜线字形。

## 第三轮修订（2026-10-22）：两级侧栏 + 页内分区标签、单一选中框、直角指示器、应用配置条目与设置分组重做

### 真机截图（computer-use）看到的问题
| 反馈 | 证据 |
|---|---|
| 左侧不要第三级 | 侧栏里选中 Caddy 后展开“站点规则/运行/原文 Caddyfile”，与右侧页面重复，还把侧栏拉长、让上一级“Caddy”失去选中框 |
| 列表里应只有一个选中框 | 应用配置的每个条目本身是带 1px 边框的按钮（`Button` 当行用），所以列表是“一格一个框”，选中时再叠一个指示器；整体像表单堆叠而不是列表 |
| tabs 圆角难看 | 标签页指示器沿用列表指示器的 3px 圆角，底部 2px 橙条两端被圆角削成弧形，且带浅橙底，像一个小胶囊 |
| 应用配置条目太丑 | 每条 4 行（名称、路径、状态徽标、“只读”徽标）加边框，每条都带重复的“只读”；顶部说明与“刷新”按钮挤在列表上面；条目面板里再套面板 |
| 设置分组列表 | 每行左侧 1–7 的数字方块（分组并非顺序流程，编号没有意义）、行高 ≈ 56px、标题与说明挤在一起，且列表有一个灰底“分组”标题栏 |

### 设计决定
**1. 三级结构 = 侧栏两级 + 页内分区标签。** 系统工具（侧栏分组）→ 工具（侧栏条目）→ 具体工具配置（右侧页面顶部的标签条）。侧栏不再展开任何分区项。分区标签条是页面内容的第一行：Caddy 的“站点规则 / 运行 / 原文 Caddyfile”，AI 配置的“Claude Code / Codex CLI / Gemini CLI / GitHub Copilot CLI”；环境变量保留现有的页内标签；应用配置、工具集（已有自己的标签）不变。分区仍由 AppShell 保存（`SectionContext`），所以跨页回来保留。

**2. 一个选中框。** 选中语言只有一个运动的指示器，条目本身永远没有边框、没有选中底色（指示器就绪后）。规则：`.slide-item` 不得带 `border`、不得带自己的背景（悬停除外）；用 `Button` 做行的地方改成无边框的行元素（`role`/语义不变）。

**3. 指示器改直角、标签页用下划线。**
```
列表（竖向）                         标签页（横向）
┌──────────────────────┐            站点规则   运行   原文 Caddyfile
▌ 选中行（浅橙底）     │            ━━━━━━━━                      ← 2px 橙线，直角，沿 1px 灰色底线滑动
│ 其他行               │            ─────────────────────────────  ← 整条标签栏的 1px 发丝线
└──────────────────────┘
```
- 指示器全部 `border-radius: 0`：列表是 3px 宽的橙色竖条 + 浅橙底（直角）；标签页只有 2px 橙色下划线，**没有底色、没有圆角**，宽度等于标签文字宽度加左右各 8px。
- 标签栏下方有一条贯穿的 1px 发丝线（`--app-line`），橙线压在它上面；选中标签文字加深加粗，其他标签 `text-muted-foreground`。
- 悬停：列表行浅灰底（直角）；标签悬停只改文字色。运动参数不变：120ms `cubic-bezier(0.2, 0.7, 0.2, 1)`，reduced-motion 下跳变。

**4. 应用配置条目：平铺行，一条两行。**
```
条目                                 [刷新]
编辑器
 Zed 设置                      ○ 未发现
 ~/.config/zed/settings.json
 Neovim 初始化文件             ○ 未发现
 ~/.config/nvim/init.lua
AI 客户端
▌Claude Code 用户设置          ✓ 已发现    ← 指示器
 ~/.claude/settings.json
```
- 行高 44px：第一行名称（13px 半粗）+ 右侧状态（符号 + 文字：✓ 已发现 / ○ 未发现，11px，不只靠颜色）；第二行路径（12px 等宽字、`text-muted-foreground`、单行省略、`title` 属性给完整路径）。
- 去掉每行的“只读”徽标（整页都是只读，页面说明与详情头已写）；去掉条目面板里的二级面板与行边框。
- 分组标题（编辑器/AI 客户端/终端…）是 28px 高的小标签（12px、muted），与行同一列；整个列表是一个面板，顶部是“条目”标题行，右侧一个 sm 的“刷新”按钮（原来在说明文字下面）；“仅显示默认位置…”说明移到列表底部的一行 12px 注释，或并入页头说明（保留原文，不丢信息）。
- 详情面板头：名称（h2）+ 路径 + 状态徽标 + “只读”徽标（只出现一次）；下面是原有的事实列表与内容。

**5. 设置分组列表：title - description。**
- 去掉数字方块与“分组”灰底标题栏；每行 44px：第一行标题（13px 半粗，前景色），第二行描述（12px，muted，单行省略）；左右内边距 12px，行与行之间无间距（由指示器表达选中）。
- 选中态：指示器（浅橙底 + 3px 橙竖条），标题保持前景色（不再用 `text-selection-foreground` 改色，避免与指示器的两种强调叠加）。
- 列表面板仍 280px 宽，窄于 760px 堆叠（既有规则）。

### 不做的事
不在侧栏出现任何第三级；不做胶囊或圆角标签；不给列表条目加边框、徽标墙或编号；不为选中再加任何第二种强调（边框/角标/虚线）。
