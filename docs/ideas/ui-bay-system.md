# 舱位系统（Bay）：界面统一与完整看板

日期：2026-10-22
状态：方向已由用户确认（2026-10-22）。对应规格见 SPEC-ui-bay.md（修订并部分取代 SPEC-ui-refresh.md 的几何与间距条款）。

## Problem Statement

怎样让 UserHome 的每一页像同一台机器上的不同舱位：骨架、间距、选中语言一致，平时紧凑，需要时能把模块独立展开成完整看板，同时保留“机甲”质感，而不是退化成“小圆角加细线”的通用卡片界面？

## 上一版的遗留问题与代码证据

| 用户反馈 | 证据（2026-10-22 只读核对） |
|---|---|
| 区域各自独立，缺少连贯性 | 环境变量页用“顶部标签条 + 主体”（grid-rows），设置页是 14.5rem 主从双栏，概览用自己的 `dashboard-grid`，Caddy 与 AI 配置是纵向堆叠的 `grid gap-ui-xl`。没有共享的页面骨架。 |
| 机甲感需要设计，不是全矩形也不是全去圆角 | `.corner-ticks` 只有左上、右下两个角，且 `z-index:-1` 压在内容后面，Panel 默认不开；选中态只有浅橙底加边框。 |
| 间距不统一 | 令牌乱序：`--app-space-sm: 8px`，`md: 6px`，`lg: 8px`；页面里 gap-ui-sm/xl/2xl/3xl 各取所需。 |
| 紧凑之外要能独立开完整看板 | 现在每页只有一档密度。 |

## 用户已确认的决定（2026-10-22）

1. 看板含义：**同页展开**，不做独立窗口（独立窗口以后再评估）。
2. 需要完整看板的模块：**Caddy、服务、AI 配置、环境变量 + 应用配置**。工具集本身是工作台，不做。
3. 圆角：**统一小圆角**——容器 4px，控件 3px，状态点与开关滑块全圆；机甲感靠选中态角标与虚线框表达（用户未选“对角装甲板”）。
4. 概览页：**保留并改为舱位墙**。

## Recommended Direction

“舱位”系统：一个机架，同一套页面语法，三个独立维度分别解决四个问题。

**1. 页面语法（解决连贯性）。** 所有页面只有两层：舱头（44px：标题、一句状态、主操作、看板切换）+ 舱体。舱体只允许三种布局之一：条带（单列行列表）、看板（12 栏网格，模块 span 4/6/8/12）、主从（列表 280 + 详情）。页面之间只有内容不同，骨架不再各自发明。不做舱尾状态栏（没有数据来源，也没有明确价值）。

**2. 间距（解决不统一）。** 一条 4px 栅格，只保留 `2/4/8/12/16/24`：组件内边距 8；同一舱体内元素间距 12；舱与舱之间和页边距 16；大分区 24。旧的 sm/md/lg/xl/2xl/3xl 全部由新档位替换，并加测试禁止页面直接写任意 gap/padding 数值。

**3. 选中语言（解决机甲感）。** 平时无装饰；悬停只出现对角两个灰色角标；选中 = 四个橙色 L 形角标（实线 2px、臂长 8px）+ 1px 橙色虚线框 + 浅橙底；焦点仍是独立的实线 2px 环（选中不等于聚焦）。用多层背景绘制，不用 clip-path，不截断焦点环。选中态不只靠颜色：角标和虚线是形状，另有 aria-selected/aria-current，导航项另有文字“当前”。`forced-colors` 下改用系统色虚线 outline。动效只有选中时 ≤120ms 的步进“锁定”，页面加载没有入场动画，`prefers-reduced-motion` 下关闭。

**4. 紧凑与完整看板（解决看板）。** 每个模块同一组件两档：紧凑（概览里的舱位，3–5 行：状态、一个关键数字、一个主操作）与完整看板（舱头 `▣` 同页切换，路由多一个 `view=board` 参数，`Esc` 或“退出看板”返回，保留滚动与选择状态）。概览是舱位墙：固定顺序、跨度混排（4/8），只给“需要关注”的舱位加状态点，不做排序（部分模块没有实时状态，排序会是假的）。

## Key Assumptions to Validate

- [ ] 4px 统一圆角加角标是否仍有足够的“机甲感” —— 这是最大的审美风险；真机上看浅色主题，不行就把容器改为对角圆角（成本低，只改一个令牌组）。
- [ ] 四个模块（Caddy、服务、AI 配置、环境变量 + 应用配置）能按同一个 12 栏骨架重新编排而不丢功能 —— 每个模块单独一个任务，先写模块的看板线框再实现。
- [ ] 12 栏看板在最小窗口宽度下可用 —— 现有窗口最小尺寸需核对；窄于阈值时降级为单列，不出现横向页面滚动。
- [ ] 新增的圆角和间距断言修改清单经你批准 —— 见下方“需批准修改的既有断言”。
- [ ] 角标多层背景在高分屏与缩放下不模糊 —— 真机待人工。

## MVP Scope

- UI-B0 令牌：间距 2/4/8/12/16/24；圆角容器 4 / 控件 3；角标与虚线选中令牌；对比度与审计测试更新。
- UI-B1 骨架：`PageShell`（舱头 + 三种舱体布局）、`BoardToggle`、`useBoardView`（`view=board` 路由参数、Esc 返回）。
- UI-B2 共享组件：Panel/Bay、导航项与列表行的选中态、Button/输入的圆角。
- UI-B3 模块迁移：概览舱位墙 → 服务 → Caddy → AI 配置 → 环境变量 + 应用配置 → 设置/工具集（仅换骨架与间距，不做看板）。
- UI-B4 复核：全局审计、窄宽度、forced-colors、待人工清单与台账。

## Not Doing (and Why)

- 独立窗口 / 多窗口看板 —— 多窗口的授权、刷新同步、退出确认都要重做；以后单独评估。
- 对角装甲板圆角 —— 用户选了统一小圆角；保留为备选。
- 舱尾状态栏 —— 没有数据来源，无明确价值。
- 概览按“是否需要关注”排序 —— 部分模块没有实时状态，排序不可信。
- 侧栏固定迷你舱位 / 实时日志在紧凑舱位里 —— 新功能，不属于“修设计”。
- 新字体、渐变、发光、大阴影、clip-path —— 沿用既有边界。
- 工具集的完整看板 —— 它本身就是工作台。
- 真机桌面验收 —— 不在本机运行应用，记为待人工。
