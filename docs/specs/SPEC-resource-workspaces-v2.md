# Spec: resource-workspaces-v2

状态：2026-09-23 已获用户审批。依赖：`desktop-shell-v2`；不改变应用、配置、Homebrew 或服务的后端能力和授权。

## 目标与用户

让用户能在同一信息秩序下定位应用与配置、查找 Homebrew 软件包、检查服务状态，并清楚区分“可看”“可编辑”“不可用”及下一步操作。

## 能力与验收

- **应用和配置：**保留 Rust 搜索/过滤、精确每页 50 项、列表选择、翻页、滚动位置及配置草稿状态。列表首先呈现名称与当前支持类别，次级元数据后置；详情先给身份/状态/主要动作，再给配置文档和来源。已有的 schema 字段、预设、编辑器、diff、备份、确认和敏感值保护不得省略。只读或排除项不显示写入操作。
- **Homebrew：**统一搜索、已安装库存与包详情的行/详情布局；安装、升级、卸载按钮依据可用动作集中展示，危险动作文案明确。库存加载失败、无 Homebrew、搜索为空、部分失败均只影响所属面板，不清空其他选择。
- **服务：**用清楚的状态文本和上下文操作显示服务列表及选中详情；只让明确支持的服务执行开始/停止/重启。操作预览、确认、进度与结果保持可见且与点击的服务对应。
- 三种资源页使用同一视觉令牌、行高、分隔、悬浮/选中/键盘焦点模式；单屏同时显示列表及被选中资源的名称与主要动作。长名称、路径、来源、诊断文本能在所归属的详情面板换行或滚动，不横向撑破整个窗口。
- 在 1120×720、100%/200% 文本缩放及三种外观下，分页/过滤、配置预览/确认、包操作及服务操作保持可达；不得通过视觉更改触发额外读写或真实用户配置操作。

## 技术、目录及风格

沿用 `src/features/apps/`、`src/features/brew/`、`src/features/services/`、`src/features/operations/` 的现有 React 与 typed IPC。视觉共享仅提炼至少两处确有相同需求的 UI 原语；不增加 `appId` 分支或客户端授权决策。示例：

```tsx
<section aria-labelledby="selected-service">
  <h2 id="selected-service">{service.name}</h2>
  <p>{service.statusLabel}</p>
  <Button onClick={onPreview}>预览操作</Button>
</section>
```

语义名称、真实中文文案及现有状态类型优先于装饰图标。

## 验证

命令：`pnpm lint && pnpm typecheck && pnpm test && pnpm build`；再用隔离 HOME 的 `pnpm test:e2e` 验证真实窗口与分页。人工覆盖每个资源页的加载、空、错误、只读、危险操作、焦点和 200% 缩放；保留原有测试，不新增测试用例。

## 边界

- 始终：保护现有预览→确认→执行、安全写入、只读权限与来源说明。
- 先问：更改 IPC、字段语义、读写边界、依赖或新增测试用例。
- 绝不：用视觉可用态替代后端授权、展示密钥、对真实 HOME 执行验收变更。
