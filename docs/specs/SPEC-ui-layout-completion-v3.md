# Spec: ui-layout-completion-v3

状态：2026-10-10 已获用户审批。依赖：`ui-visual-system-v3`。替代 `desktop-shell-v2`、`resource-workspaces-v2` 和 `utility-workspaces-v2` 中与本修订冲突的页面布局细节。

## 目标

彻底迁移 Dashboard、Applications/Configuration、Homebrew、Services 和 Settings，清除新外壳中残留的旧网页式排版。任何路由都必须在最小 1120×720 内容尺寸中预览、选择并操作真实内容；窗口放大时利用额外空间，但不改变信息层级。

## 统一工作台结构

每个主路由按同一桌面结构组织：

1. 原生标题栏与全局主导航；
2. 单一上下文工具栏，包含当前页标题和至多一个主要全局动作；
3. 内容工作区，按模块采用概览行、列表/详情或列表/详情/检查器；
4. 由明确 pane 拥有的局部滚动区域。

不得保留第二套品牌标题、网页 hero、整页卡片网格、重复页标题或页面自有导航栏。列表选择、详情和检查器之间使用边界与层级分隔，不依赖卡片阴影。

## 路由验收

- **Dashboard：**首屏先呈现用户目录配置识别摘要，再呈现需注意事项、软件与服务状态和最近操作。概览使用分组行，不使用同权大卡片。
- **Applications/Configuration：**目录/筛选、结果列表和配置详情保持同时可辨；选中应用后配置文档、识别证据、能力与安全状态均有固定位置。分页、筛选和选择不得被详情内容挤出视口。
- **Homebrew：**工具栏、清单列表和详情使用同一分栏；长命令结果、错误和确认信息在详情 pane 内滚动。
- **Services：**服务列表和详情持续可见；运行状态、配置有效性和操作结果相互独立，不因空间不足被折叠成不可见内容。
- **Settings：**七组设置保留列表/详情布局；详情内字段、说明、反馈和危险区按统一节奏排列。200% 缩放时可在详情 pane 滚动到最后一个操作。

## 尺寸与滚动

- 默认及最小窗口内容尺寸为 1120×720；允许原生边框放大及缩回最小尺寸，继续禁止最大化、全屏和标题栏双击缩放。
- `html`、`body`、`#root` 和 shell 不产生文档级横向或纵向滚动。工具栏和 pane header 固定在所属网格位置；长列表、详情、编辑器、检查器和设置详情各自滚动。
- 所有 grid/flex 子项显式允许收缩（例如 `min-width: 0` / `min-height: 0`）；长名称、安全相对路径、版本、错误和操作文案换行或在所属 pane 中滚动，不推宽文档。
- 100% 与 200% 文本缩放下，主要内容和操作可通过键盘到达；不得用 `overflow: hidden` 静默裁掉可操作内容。
- 每个主路由都必须完成旧布局审计：组件标记、共享样式和测试选择器一起迁移。只修改 Dashboard 或全局背景不能算完成。

## 状态与交互

Loading、empty、partial、warning、error 和 ready 在原位置表达，并保留可读文案与 ARIA live 语义。路由切换不抢走导航焦点；列表选择、草稿、分页和安全确认流程保持现有行为。

## 边界

### 始终

- 保留原生 traffic lights、拖拽区和交互 no-drag 区。
- 保留所有现有功能入口和安全确认。
- 对五个路由逐一验收，而不是从共享 CSS 推断完成。

### 先问

- 改变最小窗口尺寸、调整业务流程、增加响应式手机布局或新增测试用例。

### 绝不

- 通过隐藏错误、详情、识别证据或主操作来满足无溢出断言。

## 验证

运行现有前端检查和隔离 HOME 的 E2E。自动断言文档视口无溢出，并人工确认每个声明滚动 pane 的首尾内容可达；分别记录五个路由在 1120×720、放大窗口、100% 和 200% 文本缩放下的结果。
