# Spec: ui-correction-acceptance-v3

状态：2026-10-10 已获用户审批。依赖：`ui-visual-system-v3`、`ui-layout-completion-v3`、`home-config-recognition-v3`。本规格补充并在冲突处替代 `visual-acceptance-v2`。

## 目标

以跨路由、跨外观、跨缩放的证据证明本次 UI 纠偏完整完成，并证明 UserHome 的首要任务——用户目录配置识别——在真实状态中清晰可用。

## 完成门槛

1. Dashboard 首个主要内容分组为用户目录配置识别；显示真实 snapshot 的分类计数、证据、安全相对路径、完整性及进入本机识别列表的操作。
2. Applications、Homebrew、Services、Settings 与 Dashboard 全部迁移到同一工作台结构；不存在旧 hero、旧卡片网格、重复标题、页面私有导航或未使用统一令牌的遗留区域。
3. System、Light、Dark 均按偏好渲染；切换即时且不丢失状态。默认仍为 System，已有偏好继续生效；任一模式不得被强制映射为 Dark。
4. 五个主路由的正文、辅助信息、标题、表单和资源行符合统一字号/行高/控件尺寸；同语义组件的计算样式一致。
5. 1120×720 及更大窗口、100%/200% 文本缩放下，文档视口无横向或纵向滚动；所有长内容与主要操作在声明的 pane 内可滚动到达，无裁切和遮盖。
6. 用户目录发现的 loading、ready、empty、partial、error、restricted 均可区分；partial/error 不删除仍有效的数据；四种覆盖级别的计数守恒且与 catalog 总量不混淆。
7. 键盘焦点、路由选择、分页、筛选、草稿、外观切换、配置预览/确认、Homebrew/服务操作、设置保存与确认行为无回归。
8. 普通文本和图标实际对比度 ≥ 4.5:1；焦点、边界及选中态 ≥ 3:1。状态不是仅靠颜色表达。
9. 无新增扫描权限、无任意路径 IPC、无绝对 HOME/用户名展示、无未知配置内容读取、无发现导致的权限提升。

## 验收矩阵

每个路由至少记录以下组合：

- 外观：System（分别跟随系统 Light 与 Dark）、Light、Dark；
- 文本：100%、200%；
- 窗口：1120×720、一个放大尺寸；
- 状态：正常，以及该路由至少一个 loading/empty/partial/error 状态；
- 输入：长应用名、长安全相对路径、长错误文案和中英文混排。

每条证据记录路由、组合、检查项、实际结果、缺陷编号和复测结果。未执行、缺少设备或不具备签名权限的项目必须标记“待验证”，不得写成通过。

## 自动化与人工验证

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm check
pnpm test:e2e
pnpm build:unsigned
```

自动化至少维持现有测试并更新与新信息层级冲突的断言。已批准少量无新依赖的 discovery DTO、计数 selector 与 stale snapshot 定向测试；其他新增测试、依赖或视觉基线工具仍须先取得用户同意。人工验收使用隔离/一次性 HOME，不修改真实用户配置；自动化成功不能替代外观、缩放、对比度和滚动的人工证据。

## 退出条件

只有五个路由和用户目录状态矩阵全部有证据，且没有阻断预览、识别或主要操作的缺陷时，UI 纠偏才能标记完成。发布签名、公证、CI 和硬件关口继续单独记录，不由本规格自动关闭。
