# /ship

加载并遵循 [shipping-and-launch](../shipping-and-launch/SKILL.md) 技能。此命令是上线前审查，不是部署、推送或自动修复授权。

## 并行专项审查

针对用户指定范围，或当前暂存改动及待发布提交，使用当前运行环境的代理工具，在同一轮中并行启动：

1. `code-reviewer`：审查正确性、可读性、架构、安全性和性能。
2. `security-auditor`：审查漏洞、威胁模型、OWASP Top Ten、秘密处理、认证授权和依赖风险。
3. `test-engineer`：分析正常路径、边界、错误路径和并发场景的测试覆盖。

给每个代理提供完整范围和只读审查要求，要求返回完整专项报告。代理相互独立，不共享可变状态、不调用彼此，也不再启动子代理。仓库或用户自定义的同名代理优先于插件默认代理。

先核对当前实际可调用的代理，不能只根据目录是否存在就断言代理不可用。如果执行环境确实缺少代理工具或必要角色，明确报告审查不完整；禁止把主会话的模拟审查冒充独立报告，或据此给出 GO。

仅当变更不超过 2 个文件、少于 50 行，且完全不涉及认证、支付、数据访问、配置或环境变量时，才可跳过并行专项审查。其他情况默认执行完整审查。

协作边界见 [orchestration-patterns](../../references/orchestration-patterns.md)。

## 主会话汇总

等待全部专项报告返回后，由主会话去重并汇总：

1. 代码质量：严重或必须修复的问题，以及失败的测试、静态检查和构建。
2. 安全：将 Critical、High 风险作为上线阻塞项，并交叉核对代码审查中的安全发现。
3. 性能：核对性能发现；适用时使用有来源的 Core Web Vitals 数据。
4. 可访问性：核对键盘操作、屏幕阅读器和对比度，参考 [accessibility-checklist](../../references/accessibility-checklist.md)。
5. 基础设施：核对环境变量、迁移、监控和功能开关。
6. 文档：核对 README、ADR 和变更记录。

## 决策输出

输出一份中文报告，包含：

- **上线决定：GO 或 NO-GO。**
- **阻塞项：** 来源角色、严重程度、具体 `文件:行号` 和修复要求。
- **建议修复：** 重要但非阻塞的问题。
- **已接受风险：** 仅记录用户明确接受的风险及缓解方式。
- **回滚方案：** 触发信号、明确步骤和恢复时间目标。
- **完整专项报告：** 保留三个角色的原始结论与证据。

任何专项出现 Critical 问题时，默认 NO-GO，除非用户明确接受对应风险。缺少回滚方案不得判定 GO；证据不足或审查不完整时明确说明，不擅自补造成功结论。
